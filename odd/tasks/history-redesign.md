# History redesign

Objective: the admin "Historial" section follows the "8 · Historial" design (#356, #357, epic #312): live search, type chips with counts, entries grouped by day, Antes / Después corrections and on-site registrations collapsed into one entry.
Branches: chained from `dev`, one per task (`feat/35N-0N-…`). Delivery: chained PRs per slice.
Test runner: Jest + PostgreSQL e2e for the backend; Vitest for pure logic and Playwright (`apps/frontend/e2e`) for flows; `pnpm verify:pr` at each slice. Visual check in Chrome at `localhost:5173`, light and dark.

## Specs

- **S1** Design source: "8 · Historial" on https://claude.ai/artifact/EQBVYtnzLp7u9BX8caRxYf (page "Historial", artboards "Historial · todo", "Historial · solo correcciones", "Historial · sin movimientos"), plus the canvas note "Historial redesign, assumptions to confirm before building".
- **S2** (#356) `GET /admin/events/:eventId/registration-history`: `filter` gains `on_site` (`manual_registration`, plus `pass_assignment` and `cash_confirmation` on registrations with a `manual_registration` audit) and `complimentary` (`complimentary_confirmation`); optional `q` (2 to 200 characters after trimming, else `400`) matching name or AKA, folio with or without hyphen, receipt, and reason only for the types that show it, accent- and case-insensitive; `counts` `{ all, corrections, on_site, complimentary }` for `q`, ignoring `filter` and cursor (`on_site` counts `manual_registration`). Same guard, scoping, order, cursor and projection. Frontend client sends `q` and the filters and reads `counts`; contract doc updated.
- **S3** (#357) Header "Historial" / "Quién hizo qué con las inscripciones del evento y por qué. Solo consulta: para corregir algo, abre la inscripción."; live debounced search "Nombre, folio, número de recibo o motivo" ("Buscar en el historial", "Borrar búsqueda"), `?q=&tipo=` in the URL; chips "Todo", "Correcciones", "Inscripciones en mesa", "Cortesías" with counts and their hints; time-zone line next to the chips.
- **S4** (#357) Grouped by day on the event's clock ("Hoy · viernes 23 de octubre", "Miércoles 21 de octubre", "N movimientos"); row with `HH:mm` mono, round type icon, title + pill (Corrección, Inscripción, Cortesía), meta line with the name linking to the registration, folio and "por <actor>"; narrow width moves the time into the meta line.
- **S5** (#357) Details: Antes / Después block for corrections (cash "Monto"/"Recibo", discipline "Pase"/"Competencias", void/expiry "Estado"; name/AKA shows "Cambió: …" without values); competencias as "Agregó"/"Quitó" chips; "Motivo “…”"; other operations keep a one-line summary.
- **S6** (#357) "Inscripción en mesa": presencial + pase(s) agregado(s) + pago en efectivo, same registration and actor within 15 minutes, collapse client-side into one entry with a summary and "Ver N operaciones" / "Ocultar N operaciones".
- **S7** (#357) Footer "Mostrando del … al … · N movimientos" + "Cargar días anteriores" (cursor paging, focus as today); no match "Nada en el historial coincide con “…”" / "No hay movimientos de este tipo" + "Ver todo el historial"; empty event "Todavía no hay movimientos" + "Ir a Inscripciones"; loading, failure, retry and denied as today.
- **S8** `--nb-*` tokens in both themes, 44px targets, 4.5:1 contrast, no horizontal page scroll at phone width; contracts and `frontend-architecture.md` updated when behavior changes.
