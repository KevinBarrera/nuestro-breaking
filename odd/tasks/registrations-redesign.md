# Registrations redesign

Objective: the admin "Inscripciones" section follows the "7 · Inscripciones" design (#344, #345, #346, epic #312): a listed and filterable roster, a detail with a summary strip, cards and two-step correction modals, and Nueva inscripción as a 3-step flow.
Branches: chained from `dev`, one per task (`feat/34N-0N-…`). Delivery: chained PRs per slice.
Test runner: Jest + PostgreSQL e2e for the backend; Vitest for pure logic and Playwright (`apps/frontend/e2e`) for flows; `pnpm verify:pr` at each slice. Visual check in Chrome at `localhost:5173`, light and dark.

## Specs

- **S1** Design source: "7 · Inscripciones: lista, detalle y correcciones" and "Nueva inscripción en mesa (3 pasos)" on https://claude.ai/artifact/EQBVYtnzLp7u9BX8caRxYf (page "Inscripciones", 11 artboards), plus the canvas note "Inscripciones redesign, assumptions to confirm before building".
- **S2** (#344) `GET /admin/events/:eventId/participants`: `q` optional (2 to 200 characters when given), optional `status` (`pending_payment` | `confirmed` | `voided`, else `400`), `counts` `{ all, pending_payment, confirmed, voided }` ignoring `status`, `passes` `{ name, passClass }[]` per result; same order, paging, guard and escaping. Frontend client reads them.
- **S3** (#345) List: header "Inscripciones" / "Busca una inscripción para revisarla o corregirla. Para inscribir a alguien en la entrada, usa Nueva inscripción." and "Nueva inscripción"; live debounced search "Nombre, correo, AKA, folio o número de recibo" with "Borrar búsqueda", state in the URL; chips "Todas", "Confirmadas", "Pendientes de pago", "Anuladas" with counts; table card with "N inscripciones" / "N resultados" and rows (name + AKA / "Sin AKA", folio / "Sin folio", pass + competitions, status pill, chevron); no-match "No encontramos a nadie con “…”"; empty event "Aún no hay inscripciones" with the three "Para recibir inscripciones en línea" steps.
- **S4** (#345) Detail: name title, "AKA …", "Ir a check-in"; summary strip "Folio", "Estado", "Total de pases", "Cobrado en efectivo" with the difference text; cards "Pases", "Pago en efectivo", "Participante" (no email or phone: the API has none); footer "Cada corrección pide un motivo y una revisión antes de guardarse. Queda en el historial con tu nombre."; pending, voided, void, several passes and $0 keep working.
- **S5** (#345) Corrections (T3: layout, shared two-step modal, pago and nombre; T4: competencias and disciplina) ("Editar competencias", "Cambiar disciplina", "Corregir pago", "Corregir nombre o AKA") as a two-step `Modal`: "Paso 1 de 2 · Cambios" (form + "Motivo", 500 max) and "Paso 2 de 2 · Revisión" (Dato / Antes / Después + motivo); same API calls and validations; success notice inside the affected card.
- **S6** (#346) Nueva inscripción: one screen, steps "Participante", "Pases", "Cobro" and "Inscripción confirmada" with the folio; step 1 creates the registration; base pass radio + its competitions + add-ons requiring their pass; "Monto recibido" prefilled and warning only; "Número de recibo" required; $0 confirms without cash; "Inscribir a otra persona" resets; "Continuar venta" resumes at "Pases".
- **S7** `--nb-*` tokens in both themes, 44px targets, 4.5:1 contrast, no horizontal page scroll at phone width; contracts and `frontend-architecture.md` updated.
